В рамках ДЗ был создан проект, в программе которого можно создавать ингредиенты, объединять их, увеличивать количество порций и формировать общий список покупок. В папке срс реализованы 4 основных класса и пустой init, который был нужен для правильного импорта (инф. из Лекции 7).
Пройдем по основным классам из папки срс.
1) Ингредиенты. Этот класс отвечает за ингредиент рецепта. Он хранит 3 осн. значения: нзвание, количество, единица измерения (г. кг и тд). Также в нем количество реализовано через @property, чтобы при изменении проверять, что оно положительное, если нет - ошибка. Реализ метод стр для вывода ингредиента, репр для технического отображения объекта в списках, eq для сравнения ингредиентов через ==, также стоит упомянуть, что 2 ингр. считаются одинковыми, если у них совпадают нэйм и юнит.
2) Рецепты. Класс отвечает за рецепты. Рецепт хранит тайтл (название блюда) и ингредиентс(список ингредиентов). Метод инит создает рецепт, принимает название блюда и список ингредиентов. Чтобы один. ингредиенты не дублировались внутри рецепта они добавляются через эдд_ингредиент. Если ткого ингредиента еще нет, то он просто добавляется в список, если ингредиент с таким же нэйм и юнит уже есть, то кол-во складывается. Стат. метод ис_валид_ратио проверяет коэффициент, возвр-ет тру/фолс, фолс если это не число, если число, то если оно отрицательное. Метод сделан через статик так как он не использует конкретного рецепта, а просто проверяет число. Скейл нужен, чтобы умножать кол-во ингредиентов (вес). Метод лен позволяет возвращать кол-во уникальных ингр. в рецепте. Метод стр возвращает рецепт в читаемом видео для удоства.
3) ШоппингЛист. Класс отвечает за общий список покупок. Он нужен для того чтобы добавлять один или несколько рецептов и получать итоговый список всех ингредиентов. Внутри класса есть список айтемс. В нём хранятся элементы в виде кортежей. То есть каждый элемент хранит сам ингредиент и название рецепта, из которого он был добавлен. Это нужно, чтобы потом можно было удалить все ингредиенты, относящиеся к конкретному рецепту. Метод эдд добавляет рецепт в список покупок. Он принимает сам рецепт и количество порций. Если оно <= 0, выбрасывается ошибка, потому что нельзя добавить рецепт на ноль или отрицательное количество порций.Перед добавлением рецепт увеличивается через метод скейл. Например, если в рецепте было 500 г муки, а мы добавляем рецепт на 2 порции, то в список покупок попадёт 1000 г муки. Метод ремув_ресайп удаляет все ингредиенты, которые относятся к рецепту с указанным названием. Если рецепта с таким названием нет, ничего не происходит. Ошибка не выбрасывается, потому что по условию в такой ситуации список должен просто остаться без изменений. Метод гет_лист формирует итоговый список покупок. Он проходит по всем добавленным ингредиентам, объединяет одинаковые ингредиенты с одинаковыми нейм и юнит, складывает их количество и возвращает список объектов ингредиентов. Для объединения используется ключ. Это нужно, чтобы одинаковые продукты в одинаковых единицах измерения складывались. Например, мука в граммах будет складываться с мукой в граммах. Но мука в граммах и мука в килограммах автоматически не объединяются, потому что у них разные юниты. Также итоговый список сортируется по названию ингредиента, чтобы результат был более аккуратным и читаемым. Метод _эд_ нужен для объединения двух списков покупок через оператор +. Он создаёт новый объект ШоппингЛист, добавляет в него элементы из первого и второго списка, а исходные списки не изменяет.
4) Диетический. Класс отвечает за диетический рецепт. Он является наследником класса рецептов, потому что диетический рецепт это тоже рецепт, но с дополнительной информацией о типе диеты, диетическая. Класс хранит всё то же самое, что и обычный рецепт: название блюда и список ингредиентов. Но дополнительно он хранит диет_тайп, то есть тип диеты. Метод инит создаёт диетический рецепт. Внутри него используется супер инит (title, ingredients), чтобы вызвать конструктор родительского класса рецептов. Метод скейл переопределён, потому что после масштабирования должен вернуться не обычный рецепт, а именно диетический. Это важно, чтобы у нового рецепта сохранился тип диеты. Например, если был веганский рецепт, то после увеличения порций он должен остаться веганским. Метод стр возвращает диетический рецепт в читаемом виде. Он выводит название рецепта, тип диеты и список ингредиентов. Это нужно для удобного отображения объекта.


Далее перейдем к тестам. 
Для тестов создана отдельная папка тестс. В ней лежат тесты для основных классов проекта.

1)  пустой файл инит пай 

2) Файл тест ингредиентов проверяет класс Ингредиент: создание ингредиента, строковое отображение, проверку положительного количества и сравнение ингредиентов.

3) Файл тест рецептов проверяет класс рецептов: создание рецепта, добавление ингредиентов, объединение одинаковых ингредиентов, проверку коэффициента, масштабирование, метод лен и строковое отображение.

4) Файл ШоппингЛист проверяет класс ШоппингЛист: добавление рецепта, проверку количества порций, удаление рецепта, ситуацию когда рецепта нет, суммирование одинаковых ингредиентов, сортировку списка и объединение двух списков покупок.

Тесты запускаются через pytest.

Поговорим о requirements.txt. Файл requirements.txt нужен для хранения зависимостей проекта. В нём у меня указан только пайтест. Установка зависимостей производится так: (баш) pip install -r requirements.txt, (на виндовс) py -m pip install -r requirements.txt. 

Далее про .гитигнор. Он нужен чтобы в гит не добавлялись лишние технические файлы. Объясню содержимое. 
__pycache__/ и *.pyc это служебные файлы, которые создаются автоматически.

.venv/ и venv/ это виртуальные окружения. Их не нужно загружать на гитхаб , потому что они могут быть большими и создаются заново через requirements.txt.

.env файл для переменных окружения и секретов, его не нужно загружать в репозиторий.

.idea/ настройки пайшарм.

.vscode/ настройки вс код.

.pytest_cache/ кэш, который создаётся после запуска тестов.
